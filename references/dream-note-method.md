# 梦境图与梦境手记

## 何时生成

只有在完整报告结束、用户明确同意生成后，才进入本流程。用户拒绝、犹豫或只想结束时，不生成图片，也不继续劝说。

## 梦境图取材顺序

1. 以用户的梦境原话为最高优先级，保留梦中真实出现的场景、人物、物件和空间关系。
2. 使用用户确认过的主要情绪决定光线、色彩、空间气氛与画面张力。
3. 报告中的解释只用于理解氛围，不得反向添加梦中没有的核心人物、物件或象征。
4. 梦境信息不足以确定某个视觉细节时，保持模糊、遮蔽或留白，不擅自补成具体事实。

## 梦境图提示词

将花括号中的内容替换为当前梦境材料，并保留其余视觉约束：

```text
生成一张 4:3 横向梦境图。

梦境场景：
{根据用户梦境原话整理的具体场景}

关键视觉元素与空间关系：
{梦中真实出现的 3–5 个主要元素，以及它们的位置和关系}

情绪与感受：
{用户确认过的主要情绪}

视觉方向：
朦胧、诗性的超现实梦境绘画，半写实但明显不是现实照片。
人物、建筑和物体保持可辨认，具体细节被柔和光线、薄雾与
相互渗透的色彩轻轻溶解。空间可以出现梦中特有的漂浮、
延伸、失重、尺度变化或不合逻辑的连接。

使用柔焦、漫射光、轻微光晕、低对比边缘和细腻的绘画质感，
让整个画面像一段正在消散但仍能被记住的梦。
根据梦境本身保留明亮、孤独、压迫或不安，不强行处理成唯美。

画面要求：
4:3 横向构图；不要照片级写实或过度清晰的材质细节；
不出现文字、字幕、边框、UI 或拼贴；
不添加梦中没有的核心人物、物件或解释性象征。
```

## 梦境手记排版

梦境手记是一张适合保存和回看的完整竖向长图，不是网页记录，也不拆成多页。视觉重点始终是梦境图、梦境原文和完整报告。

- 使用深色、克制、私密的整体背景，正文保持清晰可读。
- 顶部标题与两个栏目标题构成统一层级，不在正文中增加装饰。
- 梦境原文与完整报告保持一致的正文字号、行距、颜色和段落间距。
- 保留完整梦境原文与完整报告，不删节，不用缩小正文字号换取更短画布。
- 画布高度随内容增长，导出前检查文字是否缺失、截断或溢出。

## 使用 HTML 模板

使用 `../assets/dream-note-template.html` 作为内部渲染器。复制模板到临时 HTML 后，只替换以下五个占位符：

- `{{DREAM_TITLE}}`：从梦境中提炼的简短标题。
- `{{DREAM_DATE}}`：当前日期或用户提供的梦境日期。
- `{{DREAM_IMAGE_SRC}}`：已生成的 4:3 梦境图路径或内嵌图片数据。
- `{{DREAM_TEXT_HTML}}`：完整梦境原文，按自然段转换为普通 `<p>`，不得改写或删节。
- `{{REPORT_HTML}}`：完整解梦报告，所有自然段按原顺序转换为普通 `<p>`，不得删节，也不使用粗体、引用、核心句、标签或其他特殊格式。

模板不识别固定报告栏目，也不根据关键词猜测内容类型。梦境原文与解梦报告使用完全相同的正文样式；报告中的所有段落连续排版，“另一种可能”等内容仍留在正文叙述中。

## HTML 转义

所有写入文本位置的动态内容都必须先做 HTML 转义，再替换占位符。转义顺序从 `&` 开始，将 `&`、`<`、`>`、`"`、`'` 分别转换为 `&amp;`、`&lt;`、`&gt;`、`&quot;`、`&#39;`。标题和日期在转义后直接替换；梦境原文和报告在转义后，按自然段包裹为普通 `<p>`。

`{{DREAM_IMAGE_SRC}}` 只使用本次生成的本地图片路径或内嵌图片数据，不接受来自梦境文本的可执行内容。

## 渲染与交付顺序

1. 先按梦境图提示词生成 `梦境标题-梦境图.png`。
2. 完成 HTML 转义并填入五个占位符。
3. 渲染页面时只截取 `.dream-note`，生成 `梦境标题-梦境手记.png`。
4. 检查长图中的梦境原文和完整报告没有缺失、截断或溢出。
5. 在对话中直接交付独立梦境图与完整梦境手记两个 PNG 文件。HTML 只是内部渲染器，不向用户提供下载按钮。

## 输出

1. `梦境标题-梦境图.png`：4:3、无文字的独立梦境图。
2. `梦境标题-梦境手记.png`：一张完整竖向长图 PNG，顺序为标题与日期 → 梦境图 → 梦境原文 → 完整解梦报告。

梦境手记不拆分为多张，不通过缩小正文字号压缩内容；画布高度随正文增长。
